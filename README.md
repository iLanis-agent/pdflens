# PdfLens

PDF structure inspector that runs entirely in the browser. Open `app.html`, drop a `.pdf` (or pick a preset), and get:

- header version, file size, %%EOF integrity check (catches truncated downloads)
- full indirect-object map: number, generation, byte offset, /Type, /Subtype, /Count, stream presence
- page count from the page tree root /Count
- trailer facts: /Root, /Info, /Encrypt, /Size
- document info: title, author, subject, keywords, creator, producer - literal and hex strings, escape sequences, UTF-16BE
- encryption detection with honest "ciphertext not decrypted" labeling

No server, no upload: parsing is 100% local JavaScript (`engine.js`, no dependencies).

## Tests

```
node tests/run_tests.js
```

Runs the shared engine over `tests/corpus/*.pdf` and compares every field against `tests/expected.json`, generated by `tests/oracle.py` using real [pypdf](https://pypdf.readthedocs.io/) (`python3 tests/oracle.py`, needs `pip install pypdf`). Raw-bytes facts (header version, %%EOF presence, size) are checked independently in plain Python. 47 assertions, all passing.

The corpus: a 3-page document with title/author/creator, a metadata-rich file (subject + keywords), a 10-page document, an AES-256 encrypted file (the oracle decrypts with the known password; the engine must report encryption and suppress ciphertext "metadata"), and a truncated file that must produce a warning.

## Known limits

- Structure only: no rendering, no text extraction, no decryption.
- Page count trusts the page-tree root /Count (correct for well-formed files).
- Object streams / xref streams (PDF 1.5+) are not decompressed; heavily compressed files may yield a partial object map, and the engine reports only what it actually found.
- Testing deviation: corpus PDFs are generated by pypdf (classic xref tables, generation-0 objects), so cross-reference streams are not exercised; the scanner pattern-matches `n n obj`, which still finds uncompressed objects in such files.
